# Стиль коду

Ці правила застосовуємо до всіх наступних змін у проєкті.

- Пояснювальні коментарі пишемо українською: вони мають пояснювати причину, гарантію або неочевидну поведінку коду.
- Короткі структурні розділювачі на кшталт `// Server`, `// Validation` чи `// UI` можна залишати англійською.
- Назви API, типів, полів даних, діагностичних кодів і зовнішніх контрактів не перекладаємо.
- Короткі імпорти, сигнатури, виклики, масиви й умови тримаємо в одному рядку, якщо це лишається читабельним.
- Орієнтир ширини рядка — приблизно 110 символів, але це не жорстка межа для неподільних рядків або зрозумілішого виразу.
- Великі об'єкти, складні булеві умови та вкладені callback-функції розбиваємо за логічними частинами.
- Не стискаємо код ціною прихованої поведінки, складного diff або погіршення налагодження.
- Стилістичне редагування не поєднуємо зі зміною логіки без окремої причини та перевірки.
